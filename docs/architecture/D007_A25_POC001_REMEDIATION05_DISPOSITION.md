## 1. Approved narrow implementation and limits

### R05-1 (P2-R04-1) — bounded XML parser
- In existing `poc/001/src/dav-xml.mjs` and directly associated local tests/mutations only: reject hostile depth/element/namespace/attribute growth **during tokenization/before unbounded allocation**, with deterministic `DAV_XML`/malformed fail-closed; export shall return **503 export_incomplete**, not partial `200`, without writes. Do not rely on JavaScript call-stack overflow or Node OOM as a protection.
- Apply explicit conservative POC input ceilings to be enforced and pinned by tests: **MAX depth 64 nested elements; MAX total XML elements 10,000; MAX attributes per element 64; MAX total attributes 10,000; MAX namespace declarations per document 256** (lower stricter internal limits are permitted only if documented and positive fixtures pass). Preserve existing **MAX_PROPFIND_BYTES=2,000,000** rather than increase it. Cap namespace-map work; avoid `new Map(parent.ns)` on every element when no `xmlns*` changes; bounded copy only when necessary, or equivalent proven efficient implementation.
- Ensure whole-tree R04 structure validation cannot recurse over attacker-supplied unbounded depth (early depth gate and optionally iterative validation); text/DOM memory is bounded by pre-existing XML byte ceiling plus explicit element/attribute caps. Preserve URI-based namespace matching, default/different prefixes and all Q1a–e gates, permitted legal property shapes inside supported profile, XML escaping/DTD/entity refusal and wrong-parent failure. No general-purpose XML library or new dependency.
- **QA performance target (local, 2-vCPU Linux Node v22.23.5 reference):** independent tests of the historical 442KB/396KB adverse XML fixtures in isolated child process must fail closed **without process crash/OOM**, including with `--max-old-space-size=256`, and **each complete in under 2 seconds** under documented local conditions; measure exit status, elapsed time and peak RSS, disclose variation. No manual increase of Node heap is an acceptable "fix". If practical environment is not comparable or test fails, mark NOT_RUN/PARTIAL and STOP for Design; do not falsify a hard PASS. The ceiling is local acceptance evidence, not a universal end-to-end provider SLA.

### R05-2 (P2-R04-2) — minimal explicit PROPFIND request profile
- In existing `poc/001/src/webdav-adapter.mjs` only: replace **empty-body/allprop PROPFIND** with explicit body selecting **only `DAV:resourcetype`**, retaining the already-authorized `Depth` semantics, loopback-only transport, credential/host/port restrictions and existing error/result mapping. Use DAV namespace URI (prefix may differ), set proper XML request `Content-Type`, correct `Content-Length` and maintain response/body deadline.
- Adapt only the in-repo synthetic WebDAV mock/test fixtures as needed to meaningfully **assert request body's exact semantics**, and test that a simulated locked record/allprop-capable server returns the minimal requested property set rather than unsolicited lockdiscovery/current-user-principal `href`. The adapter must **never silently retry with empty-body/allprop**, invent a valid listing, drop an unexpected record or weaken R04 structural fail-closed. If a server returns unsupported extra DAV structure despite explicit request, return **503 export_incomplete** and declare unsupported provider behavior; do not claim real Nutstore compatibility.
- Update `poc/001/README.md` and `QA_HANDOFF.md`: explicit resourcetype-only request, conservative response profile, legal `lockdiscovery`/`current-user-principal` with nested `DAV:href` may still be rejected **if returned**, actual provider compliance NOT_RUN. Preserve 2xx-only collection proof and valid 0/2-record export/restore, Q1c nested-response rejection.
- No production HTTPS, general-purpose DAV parser, provider-specific fallback or new functionality.
