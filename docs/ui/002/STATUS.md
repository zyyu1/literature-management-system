## Design decisions

- **UI-D001 APPROVED:** Projects Home uses Cards / List switchable hybrid, cards as default and responsive single-column mobile presentation.
- **UI-D002 APPROVED:** Project create/edit/archive/restore and permanent delete with a distinct second confirmation; permanent deletion removes only Project and its associations, never global papers, reading states, notes, quotes or Zotero content.
- **UI-D003 APPROVED:** Standard Home display with Project name/description, literature total, three-state counts, reading progress bar, search, sorting and archive browsing in both Cards/List views.
- **UI-D004 APPROVED (LAYOUT ONLY):** Desktop literature table; compact phone literature cards; tablet responds to available width. All views share global literature identity/status and Project associations.
- **UI-D004.1 APPROVED (STANDARD MANAGEMENT; UNLINK SCOPE AMENDED):** Current-Project search/status filtering, sorting, Zotero selection/one-time Collection import, multi-select, bulk global reading-state updates, and scope-selectable unlinking (current Project only or all Projects), always preserving the canonical literature record and notes.
- **UI-D005 APPROVED (LAYOUT ONLY):** Desktop two columns (left: structured Research Notes; right: Key Quotes + Zotero metadata); mobile single column; tablet adaptive. One global note per canonical paper.
- **UI-D005.1 APPROVED (SAVE BEHAVIOR):** Autosave plus Save Now, remote-acknowledged Saved state, explicit local-draft/offline/failure/conflict states and no silent multi-device overwrite; WebDAV support requires POC-001.
- **UI-D005.2 APPROVED:** Key Quotes can be entered manually or created by selectively choosing existing Zotero highlights; preserve annotation/page reference when available; no bulk automatic synchronization or source-edit side effects.
- **UI-D005.1a APPROVED:** Five independent Markdown note fields, common formatting toolbar, safe preview and Typora-compatible full-note Markdown export; retains autosave/Save Now and concurrency rules.
- **UI-D005.2a APPROVED:** Right-hand highlight picker panel on desktop, full-screen selection UI on phone, with search, multi-select, source-text preview, and already-linked marking; no automatic all-highlight sync.
- **UI-D004.2 APPROVED:** Title, authors, publication year, global reading status and Actions menu on desktop; essential title/authors/year/status plus reachable actions on mobile; sort by year, title, reading status or date added to current Project.
- **UI-D005.1b APPROVED:** Each of the five Markdown fields independently switches between Edit and Preview, defaulting to Edit; switching preserves source/draft and never bypasses safe saving.
- **UI-D005.2b APPROVED:** Progressive Zotero source-open fallback: precise highlight if supported, then paper/PDF with page hint, then copy excerpt; retain Key Quote/comment even if source unavailable. External navigation success cannot be assumed.
- **UI-D004.3 APPROVED:** Default Project Literature sorting is Date Added to the Current Project descending (newest project association first); other approved sort choices remain available.
- **UI-D004.3a APPROVED:** Search only literature linked to the current Project, matching Zotero Title, Authors, Publication Year and DOI; compose with the existing global reading-state filter and current sort.
- **UI-D004.3b APPROVED (AMENDED):** Graded import/batch confirmation and partial-result feedback; before unlink confirm chosen scope, protecting Zotero/global notes, and support failed-only safe retry.
- **UI-D004.3b-R1 APPROVED:** Per-item/bulk unlink selector: default Current Project only or All Projects including current. Global unlink needs a stronger explicit confirmation; no canonical paper/status/note/quote deletion.
- **UI-D004.3-R1 APPROVED IN PRINCIPLE:** Distinct Important Papers view; UI-D004.3-R1a confirms tabs instead of a pinned section; association-level Important scope is now approved in UI-D004.3-R1b.
- **UI-D004.3-R1a APPROVED:** All Papers / Important Papers tabs, All includes all Project papers (including Important); Important shows the marked subset, without copying records. All Papers remains newest-linked-first.
- **UI-D004.3-R1b APPROVED:** Important is Project–Literature association-specific; marking/unmarking affects only the current Project's Important tab and never the global status/notes.
- **UI-D004.3-R1c APPROVED:** Important Papers sorts by the most recent per-Project Important marking timestamp descending; All Papers keeps newest linked first.
- **UI-D005.1c APPROVED:** Recover offline Markdown drafts; compare local vs remote across five fields, choose local/remote or manually merge per field; version-check the entire globally shared note again before saving, never overwrite silently.
- **UI-D004.3-R1d APPROVED:** Single-paper Mark/Unmark Important star button on desktop rows and mobile cards; equivalent Actions-menu command; Project-scoped state, no bulk-star operation authorized.
- **UI-D005.2c APPROVED:** Highlight picker defaults to PDF page order ascending; same-page highlights remain distinct and missing/unreliable page metadata must be represented honestly.
- **UI-D005.2d APPROVED:** Classified highlight-picker UI for loading, no highlights, no search matches, network failure, access/permission failure and missing upstream source, each with truthful targeted recovery actions and Key Quote preservation.
- **UI-D005.2e APPROVED:** Existing Key Quote remains unchanged by Zotero source edits until explicit review; compare saved/current highlight, choose Keep or Update excerpt only, preserve personal comment and source identity; never infer deletion from transient failure.
- **UI-D005.2f APPROVED:** Zotero highlights grouped under their original PDF attachment names, with accessible expand/collapse and ascending PDF-page order inside each group; cross-group selections preserve annotation and attachment identity.
- **UI-D005.2g APPROVED:** When an original Zotero annotation is unavailable, user may explicitly select and confirm a new highlight; retain same Key Quote excerpt/comment and inspectable previous-source provenance. No automatic relinking or source edits.
- **UI-D004.3-R1e APPROVED:** Show counts on All Papers and Important Papers; preserve separate user-selected sorts when switching tabs within an open page session; a new page visit restores the existing per-tab default sorts; no cross-device/persistent preference storage.
- **UI-D004.3c APPROVED:** Phone literature cards enter explicit Select mode, exposing checkboxes, selected-count bottom batch bar for global status change and scope-confirmed association removal, plus an exit action; no permanent checkboxes or new bulk Important action.
- **UI-D005.1d APPROVED:** Five Markdown fields use a standard academic source-editing toolbar for headings, bold, italic, lists, blockquotes, code, links and math snippets, retaining secure preview, autosave and Typora-compatible export.
- **UI-D005.1e APPROVED:** Typora-compatible UTF-8 .md export filename from sanitized Zotero paper title and item key; include available bibliographic details and all five intact Markdown Research Note sections in canonical order, no PDF or Key Quotes, and distinguish unsynced draft from remote saved version.
- **UI-D005.1f APPROVED:** On detecting an available unsynced local Markdown draft, show explicit recovery dialog comparing local/remote version status and affected fields; Review & Recover opens per-field comparison, Not Now/close never deletes draft; Save requires remote revision recheck and acknowledgment.
- **UI-D005.1g APPROVED:** When unsynced note edits exist, explicitly offer Export Local Draft or Export Saved Version with accurate available/cached revision status; exporting preserves five-field Markdown and does not upload, mark Saved, resolve conflict or delete drafts.
- **UI-D005.1h APPROVED:** Clear only the precisely identified, confirmed-remote-saved and content-equivalent local draft copy when no newer edits/conflicts exist; preserve unsynced and conflict drafts; manual Discard Local Draft requires explicit confirmation, no time-based expiration.
- **UI-D005.1i APPROVED:** Markdown toolbar preserves the active selected text/caret; Edit / Preview restores the same field's edit caret and scroll position independently of the other four fields; stale positions cannot corrupt drafts or conflict decisions.
- **UI-D005.1j APPROVED:** Clearly display locally unsynced draft status, actual local edit time and affected fields; targeted Discard Local Draft warns of lost changes/remote saved-copy availability and offers Export Local Draft; only explicit confirmation may delete that identified draft.
- **UI-D005.1k APPROVED:** Export Local Draft uses `<safe-title>_<zotero-key>_LOCAL-DRAFT.md`; Export Saved Version uses `<safe-title>_<zotero-key>_SAVED.md`. Suffix reflects selected source; an offline cached confirmed-saved revision is not necessarily latest; no export writes.
- **UI-D004.3-R1f APPROVED:** Tab badges show current Project's unfiltered All Papers and Important Papers totals; active search/status-filter matches display as a separate N results label in the list area, with truthful loading/zero/error states.
- **UI-D004.3d APPROVED:** Phone Select-mode selection persists within the current Project across All/Important tabs, search and status filters, even when selected cards are hidden. Bottom bar counts all selected; leaving Project or exiting Select mode clears without writing; batch confirmation includes hidden selections and honors approved scoped safeguards.
- **UI-D004.3-R1g APPROVED:** Project-scoped Important star shortcut appears at desktop paper row right and phone paper card top-right, with equivalent Mark/Unmark Important action retained in Actions menu. Selection, navigation and other Projects' state remain separate; no new bulk Important action.
- **UI-D004.3-R1h APPROVED:** Important star and equivalent Actions menu show Saving with duplicate action suppression; update per-Project star and Important total only after confirmed remote success; on failure keep prior confirmed state and show Retry; uncertain/stale responses require reconciliation.
- **UI-D004.3-R1i APPROVED:** Desktop and phone use the same subtle neutral gray rounded numeric badge directly beside each All/Important tab label, showing only verified unfiltered current-Project totals; separate N results for filters, nonnumeric loading/unknown states, accessible tab count labels.
- **UI-D004.3e APPROVED:** Phone bulk operations show Succeeded/Failed/Skipped outcome counts and expandable failed-paper reasons, including honest unknown statuses when writes are uncertain. Retry Failed only revalidates and resubmits eligible failed papers; previously succeeded items are never repeated.
- **UI-D004.3f APPROVED:** Before a phone batch write, confirm unique total selected, number hidden by current tab/search/filter, operation and scope; expandable list covers all selected papers including hidden entries. Global reading-state impact is stated; all-Project unlink gets strengthened affirmative confirmation; cancel has no write side effects.
- **UI-D004.3-R1j APPROVED:** Important star shows Saving beside the row/card shortcut and brief local success confirmation after acknowledged remote write; definite failures appear with reasons and Retry inside that exact paper row/card. Accessible status announcements, previous confirmed state and count preserved until success; uncertain results require reconciliation.
- **UI-D004.3-R1k APPROVED:** On phone paper cards, Select mode replaces the top-right Important star shortcut with a selection checkbox; exiting Select mode restores the true confirmed Project-scoped star. Checking/selecting never changes Important, pending saves remain truthful, no bulk Important operation added.
- **UI-D005.2h APPROVED:** Each Key Quote shows its current Zotero highlight provenance by default; Source History expands a chronological original/previous/current source timeline of confirmed manual re-links, showing known PDF/page/annotation ID/reliable time and explicitly labeling unavailable or unknown metadata. No automatic re-link or rewriting saved excerpt/comments.
- **UI-D005.2i APPROVED:** Relink Source requires an old/current vs new Zotero highlight comparison before affirmative confirmation; if the original is unreachable, warn that deletion is unverified and access might be temporary. Confirmed writes update only active source plus provenance history; saved excerpt/comment stay unchanged; stale/failed/unknown writes are guarded.
- **UI-D005.2j APPROVED:** On positive remote Relink acknowledgment, close the confirmation, return to the same Key Quote, update Current Source with brief success feedback, retain expandable Source History and restore focus to the quote's source region. Cancel never writes; failures/unknown outcomes never fake success.
- **UI-D005.1l APPROVED:** On phones, show Bold, Italic, Heading, List and More; More exposes remaining approved academic Markdown tools, while desktop retains the complete toolbar. Preserve per-field caret/selection and undo/autosave, with keyboard and assistive-technology access; opening More never edits or saves.
- **UI-D005.1m APPROVED:** Local-draft recovery and remote-note conflict dialogs move focus inside, provide accessible comparison/navigation across all five Markdown fields, and restore focus to the original editor/caret or a safe fallback after close. Focus/navigation/Cancel/Not Now never save, resolve conflicts or discard drafts; remote writes remain revision-checked.
- **UI-D005.1n APPROVED:** In an active Markdown Edit field, Ctrl/Cmd+B toggles Markdown bold, Ctrl/Cmd+I italic, and Ctrl/Cmd+K link insertion; all preserve the field's valid selection/caret, honor IME and undo, and never hijack browser, OS or assistive-tech reserved shortcuts. Other commands remain in toolbar/More.
- **UI-D005.1o APPROVED:** Phone Markdown More uses a button-anchored menu when space allows, switching to a compact keyboard-aware bottom action panel when the virtual keyboard constrains the viewport. Both expose the full remaining toolset and preserve per-field selection/caret, touch/keyboard/screen-reader use; opening, closing or adapting never edits or saves.
- **UI-D004.3-R1l APPROVED:** During phone Select mode, hide individual Actions menus as well as star shortcuts; keep checkbox selection and the bottom approved batch-action bar as the available paper actions. Exit restores current verified star and per-paper Actions. In-flight Important writes, failures and uncertain results remain tracked, truthfully indicated and recoverable after exit, without accidental retry/success claims.
- **UI-D004.3g APPROVED:** Phone batch confirmation uses a scrollable modal bottom sheet with operation/scope, full and hidden selection counts, expandable list of all selected papers, and easily reached safe-area-aware Cancel/Confirm controls. All-Project unlink still requires a stronger affirmative acknowledgment; no write on dismissal.
- **UI-D004.3h APPROVED:** In Project Literature desktop rows and phone cards, subtly highlight only actual search-matched title/author/year/DOI text spans with readable accessible contrast; reuse existing search matching semantics, preserving result membership, tab counts, sorting and Zotero original metadata. No extra match-summary row.
- **UI-D004.3-R1m / UI-D004.3i / UI-D005.1p / UI-D005.2k / UI-D006:** PENDING. Select-mode Important state visibility/focus, sort-direction and batch copy/results details, adaptive Markdown More dialog layout, Relink fallback and cross-device UI acceptance.
