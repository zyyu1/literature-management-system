## 4. Outcome model and idempotency

Ledger keyed by authenticated principal ID + operationId and binds runId, exact action/resource/scope, canonical payload and precondition fingerprint; same ID with changed target/action/value/revision/scope yields 409 OPERATION_ID_REUSE and no dispatch. Check authorization before ledger lookup; replay cannot bypass expired/revoked Session or scope. Exact same key replay in same model never dispatches twice, including UNKNOWN/pending; response explicitly model-only/non-durable with saved=false. A model-confirmed replay may refer to original simulated outcome and revision, not claim current resource state or durable idempotency. New operation on a target with unresolved UNKNOWN blocked 409 until end of instance (no reconciliation mechanism authorized); unrelated resources may operate without widening the target. Ledger and state bounded by request budget; no eviction that permits replay. New instance discards all data and rejects old runId, no real cross-process recovery claim.

Four A5 outcomes exercised with test-only injection before/after commit: acknowledged model commit = 200/201 CONFIRMED with matching operationId, resource, new revision and explicit outcomeBasis=MODEL_ONLY, durable=false, saved=false, simulated=true; not a production confirmed save; conflict 412/409/428 with authorized current revision only where appropriate and dispatched=false; definite pre-dispatch rejection no state change; 202 accepted-not-committed UNKNOWN, 504 lost-ack-after-commit UNKNOWN, actual socket drop after model commit (client local UNKNOWN; no fabricated response). Unknown never saved/definitely failed or retried; retain original operation identity, quarantine affected target; no public operation lookup or background verification claim. Unexpected errors after possible dispatch and response-size issues fail conservatively UNKNOWN or close connection, never pre-dispatch DEFINITE_FAILURE. Explicitly distinguish actual model state vs client's last confirmed state. No actual durable ledger, cross-process CAS, provider acknowledgement, backup or restore claim.
