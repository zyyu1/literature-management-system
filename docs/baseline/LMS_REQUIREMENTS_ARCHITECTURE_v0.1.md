# 文献管理系统：需求与架构设计文档

> **版本**：v0.1.0-draft  
> **整理日期**：2026-11-22  
> **阶段**：Module 001 核心需求与 D007 初步方案已讨论；即将进入 Module 002（UI 与交互设计）。  
> **文档原则**：明确区分 **已批准需求 / 推荐实现 / 尚待技术验证 / 尚未裁定**，避免将预想功能误记为已完成。

## 1. 产品定位与目标

### 1.1 定位

构建一个**轻量级、独立、响应式的文献管理网页（Literature Management Website）**，服务科研项目的文献整理、阅读进度管理及文献综述笔记积累。

系统**不是 Zotero 的替代品**。用户已在多台电脑、手机和平板上使用 Zotero；本系统作为 Zotero 之上的项目组织与研究分析界面，尽可能复用 Zotero 现有的 PDF、文献元数据、批注、文件同步和阅读器能力。

### 1.2 核心目标

1. 按不同 **Project** 分类组织文献，每个 Project 有自己的文献列表。
2. 同一篇论文可属于多个 Project，但**阅读状态和研究笔记全局只有一份**。
3. 从 Zotero 导入文献信息：手动选择，以及从 Zotero Collection **一次性批量导入**。
4. 提供为**文献综述写作**设计的结构化论文详情页，笔记由用户读后自行填写。
5. 关联 Zotero PDF 高亮及原文摘录，尽可能一键返回 Zotero 中对应位置。
6. 电脑、iPad、手机等设备经互联网访问同一网页和笔记；打开 PDF 时优先交由**当前设备的 Zotero 客户端**处理。
7. 预留与独立的**个人工作台（Personal Workspace）**联动的只读 API 和页面跳转入口。
8. 优先采用简化、低成本、易迁移的方案；不重复存储 PDF。

### 1.3 非目标（当前 MVP 不做）

- 不开发自己的 PDF 阅读器，不复制 PDF 到网页服务器或独立笔记云盘。
- 不开发 Zotero 的完整替代数据库、引文编辑器或全文下载服务。
- 不要求个人工作台直接编辑文献状态或笔记。
- 不默认与 Zotero Collection 建立持续自动增删同步。
- 不在当前阶段强制实现 AI 自动总结或论文自动分析；结构化笔记以**人工填写**为核心。
- 不因网页可联网而假定移动端能直接访问电脑本地文件路径。

## 2. 用户与使用环境

- **使用者**：当前以个人科研使用为主，面向未来持续扩展。
- **终端**：多台已安装 Zotero 的电脑，以及有 Zotero App 的手机、平板；网页需响应式适配。
- **Zotero 账户**：多台电脑使用同一个 Zotero 账号，用户已开启同步。
- **PDF 文件同步**：现有 Zotero 使用**坚果云（Nutstore）WebDAV** 同步附件，部分设备的 PDF 可能尚未下载到本地。
- **网页访问范围**：通过互联网随时随地访问，而非仅限同一局域网。
- **笔记数据存储目标**：优先尝试**另一个坚果云账号**保存网页自身数据；该账号能否提供所需 WebDAV 读写能力须做 POC 验证。

> 注意：Zotero 的**条目/批注数据同步**与坚果云 WebDAV **PDF 附件同步**是不同层次。仅启用 Zotero 同步，不能证明某一 PDF 已上传并可按需下载；具体以各设备 Zotero 文件同步配置和附件类型为准。

## 3. 信息架构及核心功能

### 3.1 Project 管理

每个 Project 表示一个研究主题或科研工作项目，例如“Embodied AI Literature Review”。支持：

- 创建、查看、编辑（及按约定删除）Project。
- 进入 Project 查看其关联的论文列表。
- 展示 Project 文献总数、按阅读状态的统计。
- 同一论文可关联多个 Project（**多对多关系**）。
- 从 Project 移除关联，不会删除全局文献记录、笔记或 Zotero 原始条目。

### 3.2 文献添加 / 导入：D002（已确认）

两种操作并存：

1. **手动添加**：在 Zotero 文献库中搜索并选中一篇或多篇，关联到当前 Project。
2. **Zotero Collection 批量导入**：选择一个 Collection，将其中的文献**一次性**关联到当前 Project。

约束：

- 重复导入同一篇文献不应创建重复的全局文献记录或重复的 Project 关联。
- Collection 日后增删文献**不自动修改** Project；若需要再次导入，应由用户显式触发。
- 是否缓存 Zotero 元数据、如何刷新元数据，应在集成实现时明确，不等于 Collection 持续同步。

### 3.3 全局共享规则：D001（已确认）

- **一篇 Zotero 文献 ↔ 一条全局文献记录**（以可靠、稳定的 Zotero 标识建立映射）。
- **同一篇文献 ↔ 一份全局阅读状态**。
- **同一篇文献 ↔ 一份全局结构化研究笔记**。
- Project 之间共享以上两项；在一个 Project 中编辑，在其他 Project 中看到同样的内容。
- 文献的全局唯一键建议使用 `Zotero Library ID + Parent Item Key`；附件与批注分别保留对应标识。

### 3.4 阅读状态：D003（已确认）

状态**仅设三个**，不增加“略读”“搁置”“精读完成”等细分状态。

| 内部候选值 | 页面中文 | 英文 |
|---|---|---|
| `to_read` | 待读 | To Read |
| `reading` | 阅读中 | Reading |
| `read` | 已读 | Read |

> 内部枚举命名属于实现建议；三状态业务规则已批准。新增文献的默认状态可建议为“待读”，最终在 UI 设计/实现时确认。

### 3.5 论文详情与文献综述笔记：D004（核心内容已确认）

**Zotero 负责提供的文献基本信息**：

- 论文名称（Title）
- 作者（Authors）
- 可获取时显示年份、刊物、DOI、摘要等元数据（额外显示字段尚可在 UI 阶段调整）

**用户阅读后手动填写的结构化笔记**：

| 栏目 | 英文建议名 | 需要回答的问题 |
|---|---|---|
| 研究问题 | Research Question | 作者试图回答/解决什么问题？ |
| 观点及研究内容 | Arguments & Research Content | 核心观点是什么，具体研究了什么？ |
| 理论和方法 | Theories & Methods | 使用了哪些理论、模型、算法、实验或分析方法？ |
| 创新点 | Contributions & Innovations | 相较已有工作有什么主要贡献？ |
| 不足 | Limitations | 有哪些局限、缺陷或未解决问题？ |
| 核心原文摘录 | Key Quotes | 哪些与文章主题高度相关的原文值得保留以备综述引用？ |

设计要求：

- 保留原文，不应自动将摘录改写后冒充原文。
- 摘录可携带页码/章节、批注定位信息及**用户的相关性说明/个人评论**。
- 研究笔记存储在本系统的数据空间内，不覆盖 Zotero 原有批注。
- **“Results（结果）”未被单独指定为必填固定栏目**；如需拆分可在 UI 设计时再议。
- 多条独立 Key Quotes 是推荐交互，已通过的 Zotero 批注关联目标本身需要能够处理多个批注；具体添加/排列方式在 UI 阶段细化。

### 3.6 Zotero 高亮批注与原文跳转：D004 扩展（已批准目标）

目标工作流：

1. 用户在 Zotero 的 PDF 阅读器中高亮论文句子。
2. 文献网页能够读取/关联有关 Zotero 批注，用户选择要保存的 Key Quotes。
3. 每条摘录保留原文、定位信息（如页码和 Annotation Key）、用户评论。
4. 点击摘录，从浏览器尝试调用当前设备的 Zotero，打开相应 PDF，并尽可能定位至高亮。

实施分期建议：

- **第一阶段**：可手动关联原文与 Zotero 跳转链接，能从网页打开相应论文。
- **第二阶段**：读取并选择现有 Zotero PDF 批注，自动填充摘录及关联信息。

> **待验证**：网页到 Zotero App 的协议跳转、批注精确定位在不同设备、系统、浏览器上的行为；不能提前承诺所有平台都能精确定位句子。

### 3.7 多终端调用当前设备 Zotero：D005（需求已确认）

| 设备/情形 | 期望行为 | 实现状态 |
|---|---|---|
| 已安装 Zotero 的电脑 | 网页点击后启动**当前电脑** Zotero，打开对应文献/附件 | 待联调验证 |
| 电脑 PDF 尚未下载 | 由 Zotero 的文件同步/按需下载机制获取，随后打开 | 取决于文件可同步及配置 |
| iPhone / iPad | 网页尝试启动同设备 Zotero App 打开 PDF | 待具体机型/浏览器联调 |
| Android | 优先尝试 App 跳转，不支持时提供可用备用入口与说明 | 平台兼容性风险，待验证 |
| Zotero App 未安装或不可唤起 | 显示明确反馈及备选文献入口 | 需实现降级处理 |

核心要求：**文献关联使用 Zotero 标识，不依赖特定电脑的 PDF 绝对路径。**

## 4. 个人工作台集成：D006（已确认）

文献网页与个人工作台**保持两个独立 Web 应用**，通过经过身份验证的**只读 API**和**Deep Link** 联动。

工作台允许：

- 查看文献 Project 列表。
- 查看某个 Project 的论文数量、阅读进度及状态统计。
- 查询 Project 论文列表和文献必要摘要信息。
- 点击入口跳到文献系统中的 Project / Literature 详情页。

工作台**不允许**直接修改阅读状态、研究笔记或 Key Quotes；编辑始终在文献管理网页中进行。未来如要升级为可写集成，应重新做权限与接口裁定。

## 5. D007：部署与数据存储方案

### 5.1 已批准方向

**优先尝试：独立响应式网页 + Zotero Web API + 第二个坚果云账号作为轻量文件存储 + 安全 API。**

- 不重复上传或保存原始 PDF。
- 系统自身数据主要是 Project、关联关系、阅读状态、研究笔记、摘录和必要的 Zotero 引用信息。
- 数据格式优先考虑可移植的 **JSON / Markdown**；具体文件布局尚未定型。
- **MVP 暂不引入 PostgreSQL**；不意味着永远排除关系数据库。
- 不要求现在购买 VPS 或锁定 Vercel、Neon、Railway 等云服务商。
- 网页可互联网访问；承载网页和安全 API 的具体平台**尚未裁定**。

### 5.2 逻辑架构

```text
电脑 / iPad / 手机（浏览器）
          |
          | HTTPS
          v
Literature Management Website
          |
          +----> Zotero Web API
          |        └─ 文献元数据、Collection、批注关联信息
          |
          +----> 轻量安全 API（认证、访问控制、冲突处理）
                   |
                   v
             第二个坚果云账号（候选：WebDAV）
                   └─ Projects / Status / Notes / Quotes（JSON / Markdown）

当前设备上的 Zotero Desktop / Mobile App
          └─ 打开论文 PDF（原有 Zotero + 坚果云 WebDAV 附件同步）

个人工作台
          └─ 经授权读取只读 API，并通过 Deep Link 跳转网页
```

### 5.3 两个坚果云账户的边界

| 用途 | 所属系统 | 是否存 PDF |
|---|---|---|
| **已有坚果云** | Zotero WebDAV 附件同步 | 是，由 Zotero 负责 |
| **第二个坚果云（计划）** | 网页自身的 Project/笔记数据 | 否 |

研究笔记主要为文字，容量通常较小。但**存储容量够用不等于直接适合网页跨端数据库用途**。必须验证 WebDAV 权限、文件读写、请求配额、跨设备一致性与并发冲突。

### 5.4 关键安全原则

- **不能**将 Zotero API 凭证、坚果云应用密码或其他密钥写入公开网页前端、GitHub 仓库或公开配置。
- 不能假定浏览器直接读写坚果云 WebDAV 可行；跨域（CORS）和凭证安全需要通过**轻量安全 API**或可靠替代方案解决。
- 身份认证、HTTPS、API 鉴权、最小权限访问及必要的服务端请求限制是正式上线前的要求。
- 需要处理多设备同时编辑同一篇笔记的冲突，避免静默覆盖。
- 定期备份并验证恢复流程；“云盘同步”不能作为唯一备份手段。
- JSON / Markdown 可导出，确保未来迁移到 PostgreSQL 或别的存储层。

### 5.5 POC-001：第二个坚果云账号读写验证（**尚未执行**）

| 测试 | 通过标准 |
|---|---|
| WebDAV 可用性 | 新账号有权限进行稳定的认证、创建、读取、更新和删除测试文件 |
| 端到端读写 | 从网页通过安全 API 创建与读取一条结构化笔记 |
| 多设备一致性 | 电脑保存后，平板/手机访问能取得最新已保存版本 |
| 并发防护 | 两端编辑同一笔记，不会发生无提示的后写覆盖 |
| 故障处理 | WebDAV 离线/限流/凭证过期时有可理解的错误提示，数据可恢复或重试 |
| 备份恢复 | 可导出完整笔记数据，并从备份恢复示例项目 |
| 密钥安全 | WebDAV 凭证与 Zotero Token 不会暴露在浏览器网络响应、前端打包文件和代码仓库中 |

**决策门槛**：全部核心项通过后，才将第二个坚果云账号确定为正式数据存储；若不通过，可重新评估最小化托管数据库，不改变页面与业务模型。

## 6. 建议数据模型（概念层，未锁定文件结构）

| 概念实体 | 主要字段 / 作用 | 约束 |
|---|---|---|
| `Project` | `id`, `name`, `description`（候选） | Project 独立维护 |
| `Literature` | `id`, `zoteroLibraryId`, `zoteroItemKey`, 必要元数据缓存 | Zotero 文献标识唯一 |
| `ProjectLiterature` | `projectId`, `literatureId` | 项目/文献关联唯一；多对多 |
| `LiteratureProgress` | `literatureId`, `status` | 每篇文献全局唯一；三状态 |
| `ResearchNote` | `literatureId`, `question`, `arguments`, `methods`, `contributions`, `limitations` | 每篇文献全局唯一 |
| `KeyQuote` | `id`, `literatureId`, `text`, `page`, `section`, `annotationKey`, `comment` | 一篇文献可有多条 |

> 上述是逻辑模型，不等于已经决定使用 SQL 表。采用 JSON/Markdown 时，也应遵守相同的唯一性约束与版本管理要求。引用中的附件 Key 与批注 Key 需要区分父条目 Key。

## 7. 三个主要页面：Module 002 的输入

### 7.1 Projects 首页

- 展示 Project 列表、创建/管理入口。
- 显示每个 Project 的论文数量和阅读状态概览。
- 点击项目进入其论文列表。

### 7.2 Project Literature 页面

- 显示当前项目关联文献列表。
- 按三个阅读状态筛选/查看，改变状态时对全局文献生效。
- 通过 Zotero 搜索手动添加、或从 Collection 一次性批量导入。
- 点击文献进入详情；从项目移除关联不删除全局笔记。

### 7.3 Literature Detail 页面

- 展示 Zotero 文献标题、作者等元数据。
- 显示全局阅读状态与关联 Project。
- 提供研究问题、观点与内容、理论与方法、创新点、不足等手动编辑区域。
- 提供 Key Quotes 区域，保存原文/定位/评论、与 Zotero 批注关联。
- 提供“在本设备的 Zotero 中打开 PDF / 定位原文”入口和失败提示。

**UI 设计尚未启动**：响应式布局、导航、搜索结果展示、保存交互、空状态和错误提示都在 Module 002 细化。

## 10. 开发前尚待确认的事项

### 10.1 必须验证的技术可行性

1. 第二坚果云账号 WebDAV 是否可用，并能否承受网页笔记读写请求。
2. 托管的**轻量安全 API**如何管理会话/密钥、完成跨域请求以及防并发覆盖。
3. Zotero Web API 的授权方式、可获得的批注定位字段，以及请求配额/刷新策略。
4. `zotero://` 跳转在 Windows、macOS、iOS/iPadOS、Android 和常用浏览器上的实际行为。
5. Zotero 的 WebDAV 附件同步与按需下载，在各实际设备上的配置及表现。
6. 项目/笔记文件的数据一致性、备份和从坚果云迁移的可行性。

### 10.2 进入 UI 设计后需要裁定

- 首页 Project 卡片/列表布局、Project 创建与编辑字段。
- 文献列表展示哪些元数据、默认排序和搜索/筛选方式。
- 研究笔记的编辑保存方式（手动保存/自动保存、草稿及冲突提示）。
- 多条 Key Quotes 的视觉组织、批注选择流程、引用格式/页码展示。
- 移动端“在 Zotero 中打开”按钮的可用性提示与失败降级。
- 空列表、导入重复项、同步失败、网络离线等状态交互。

## 11. 建议执行顺序与里程碑

| 阶段 | 目标 | 输出 / 验收 |
|---|---|---|
| **01 · 需求基线** | 确认功能边界与技术原则 | **本文档（当前）** |
| **02 · UI 设计** | 完成三个核心页面的桌面/移动端布局与交互 | UI 设计稿、交互规则、用户流程 |
| **03 · POC-001** | 验证第二坚果云账号可可靠存储并同步笔记 | 可重复的读写/冲突/恢复测试记录 |
| **04 · Zotero 联调 POC** | 验证认证、Collection 导入、PDF 深链接、批注定位 | 跨设备测试矩阵、风险清单 |
| **05 · MVP 实现** | Project、文献列表、全局状态、结构化笔记、基础 PDF 跳转 | 首个可用的网页版本 |
| **06 · Zotero 批注增强** | 选择高亮批注、Key Quotes 关联、精确定位优化 | 跨设备验收结果 |
| **07 · 工作台只读联动** | 发布受保护的只读 API 与 Deep Link | 与独立个人工作台联调验收 |

> 以上为建议的实施次序，不等于所有后续功能已排定具体版本号或开发日期。实际开发前仍需锁定仓库、技术栈、运行平台与测试标准。

## 12. 一句话设计原则

> **让 Zotero 管论文及 PDF，让文献网页管 Project、阅读进度和综述笔记；让各设备上的 Zotero 打开原文，让个人工作台只读地了解科研进度。**
